# 策略质量与 Muse 验收指引

本轮覆盖数据输入、入场检查、信号生命周期、通知复核、效果评估与网页展示。目标是减少缺证据和短暂触发导致的误报；代码通过检查不等于收益或胜率已经改善。行情采集仍使用既有公开接口，邮件沿用 Muse 的连接，研究仍为手动/原有配置。

## 默认生效的检查

- `enable_entry_quality=true`：现货动量与 pre-pump 入场候选统一经过检查。缺项降为 WATCH/SETUP，不进入机会发送组。
- 至少两次盘口和已收盘 K 线的源时点各相隔 60 秒。当前输入仍须新鲜，历史 anchor 在采集时须新鲜且对齐，默认最多回看 1800 秒；中间若出现不支持的观测，也不能跳过它挑选更早的有利记录。缓存复用、同一数据重复采集不能确认自己。断档恢复、参数和版本区别见[历史锚点指引](entry-anchor-recovery.md)。
- 每次确认需要有效实际成交买入占比；默认至少 58%。15 分钟成交窗口重叠，因此这不是独立样本或独立策略投票。
- 正负 0.1% 内已观测到的双边金额分别至少 10,000 USDT。部分盘口也可证明这个金额下限，但必须标为 OBSERVED_LOWER_BOUND，不能计算完整范围的买卖盘比例或市场共振。它是可配置的观察质量下限，不是针对用户资金量的下单或滑点保证。
- 当前 5 分钟、15 分钟涨幅均不能超过默认 3% 追涨限制。保留 pre-pump 原有首次发现后确认时限和追涨限制。
- pre-pump 的正面催化、代币背景不再替代市场证据组；强候选必须有实际现货买入及现货/衍生品对齐。F 子模式比较完整且新鲜的同一 1% 盘口范围，避免截断深度被当成卖方撤单。
- 非法 OHLC、异常主动买入量、空/交叉/重复盘口显式标错；零数量档位不能证明深度范围完整。组件在快照可用时点后才收到，不能进入当时判断。

合并升级后的初始观测可能降为 WATCH：旧快照没有 0.1% 覆盖字段，需要等待足够的新鲜观测。通过 `/api/quality` 的 checks/reasons 判断原因，不能用调低阈值或补零绕过数据缺失。

## 市场买盘共振

`market_confirmation_mode=observe` 默认只记录研究对照，不改变入场资格或增加策略票数。使用当时名单中的其他币，等权计算买盘改善占比和盘口不平衡中位数；排除本币，避免自我确认。没有名单时明确标为归档样本集合，不能解读为完整市场覆盖。

改善要求完整盘口、买方绝对金额增加、买卖盘不平衡改善且达到 0.1，以及连续成交买入确认。单纯卖单减少不构成买入增强。当前本币和其他币的盘口时间必须对齐，未来/过期观测不参与。

默认至少 5 个其他币有效，且有效覆盖达到名单的 70%；否则 UNKNOWN。只有覆盖完整的盘口参与共振；价格移动也会改变范围内档位，不能将金额变化等同资金流入。改善占比至少 60% 且中位不平衡至少 0.1 标为 SUPPORTIVE；改善占比不高于 30% 且中位不平衡小于零标为 WEAK；其余 MIXED。本币也满足改善才是 `resonance=true`。这些是待检验的研究阈值，不是 CoinKarma 专有 LIQ 或已复现 Triton。

当确有足够对照结果后，可显式配置 `require` 将共振作为额外门控。默认保留 observe；观察结果、缺失成员和来源快照 ID 保存在信号 decision 中。数字波动和背景更新不单独制造新通知。

## 发送与退出观察

发送机会前用最新归档重新计算当前规则、资产风险和入场质量；若原条件已不成立，返回 `SKIP_ENTRY_NOT_CONFIRMED`，不继续发送排队中的旧机会。`current_entry_assessment` 是复核结果，原通知的 `decision` 保持不可变。真实市场风险提醒保持独立。

已产生的入场候选若连续新观测的现货主动买入均低于 45%，记录“买入支撑消失”的失效原因。一次短暂回落只暂停机会使用；数据缺失也只暂停，不冒充确定失效。沿用现有撤销政策：原通知有 SENT 回执且未超过观察期限才通知，普通观察失效不刷屏。该撤销是候选逻辑变化，不等于自动卖出建议。

## 如何检验准确性

`muse validate` / `/api/validation` 返回 `validation-v3`，网页“验证”同步展示。各规则的主评估期、辅助观察及历史迁移见[策略期限](strategy-validation.md)：

- 新信号在生成时保存评估指标与期限；只验证声明的期限。五分钟辅助表现不自动否定信号；主期限缺失不能被辅助盈利结果替代。
- RISK 单独评估终点/窗口下跌与采样跌幅、反向上涨；波动背景单独评估范围和绝对变化。旧结果在 `legacy_rules` 保留，与新声明分开。

- 按规则版本、质量参数指纹、信号类型、模块和时间窗分组；WATCH、RISK 的价格变化不混进入场正收益占比。
- 待到期、缺失终点、采样断档分别列示；旧样本沿用记录的覆盖阈值。重复/迟到报价按市场时点整理，重复报价不增加采样数。
- 同币同规则重叠窗口取最早信号。即使最早信号没有结果，也不能让随后盈利的重复信号代替它。
- 入场候选展示固定往返费用/滑点后的平均、中位收益，双倍成本压力结果，正收益占比及 Wilson 95% 描述区间。跨币和跨规则仍可能相关。
- 分别比较共振成立、不成立、未知和未记录；较早/较晚时间块分开，剔除跨分割点的结果窗口。它们仅是描述性诊断，不冒称未碰过的样本外检验或因果改善。
- 默认少于 30 个去重且覆盖的样本标记 INSUFFICIENT_SAMPLES；达到数量仍为 DESCRIPTIVE_ONLY，不自动晋级。固定期限标签没有模拟成交、止损或退出，不能称为实盘收益回测。评估对象是归档规则信号，可能未送达；不是邮件或用户持仓的收益统计。

规则版本包含质量参数指纹，参数改变立即使用新归档和冷却分组。原始记录不回写。真实云端数据尚未在本次本地修改中运行验收。

## Muse 更新步骤

1. 使用 [云端运行指引](cloud-run.md)备份数据库，保留云端 `.env`、邮件连接和游标。待本 PR 合并后更新 main 并重新安装，按既有方式重启；不要覆盖云端临时修改。
2. `/health` 应出现 `entry_quality_version=entry-quality-v2`。检查 `.env` 中新增字段，默认参数见 [示例](../.env.example)。保持 `MUSE_MARKET_CONFIRMATION_MODE=observe`。
3. 只读诊断：`.venv/bin/muse quality-report` 或认证访问 `GET /api/quality`。核对本币源时点、确认快照、盘口完整性、缺项、有效市场覆盖。首次启动/历史不足时 WAIT/UNKNOWN 正常。
4. 检查机会的 `decision.entry_quality` 和 `decision.market_confirmation`。符合历史锚点条件的旧观测可以复用；没有合格 anchor 时仍须积累至少两个不同源时点的有效观测。保留原本的批次拉取、发送前复核、`message_zh` 正文和 SENT/SKIPPED 回执流程。
5. 使用 `.venv/bin/muse validate` 保存评估报告；反馈 `rule_version`、非重叠样本数、缺失/断档、扣成本及双倍成本结果、共振分组和较晚时间块表现。样本不足时报告不足，不汇报“高准确率”。
6. 验收反馈还需包含代码提交号、主采集周期耗时、盘口范围完整率、机会被各检查拦截的数量和实际邮件样例。没有邮件回执不能声称送达。

盘口请求仍默认 100 档，未增加现有请求数量或默认权重。如果云端证实 0.1% 范围经常不足，可评估显式增加 `MUSE_SPOT_DEPTH_LIMIT` 至 500/1000；按 Binance 官方文档，100/500/1000 档请求权重分别为 5/25/50，须同时观察限流和轮次耗时。[Binance 官方盘口接口](https://developers.binance.com/en/docs/catalog/core-trading-spot-trading/api/rest-api/market)

## 离线检查

`bash scripts/check.sh` 覆盖 Python 检查、回归测试、网页脚本语法和 CLI。新回归包含缓存假确认、未覆盖/薄盘口、未来数据、未对齐来源、中间反证、本币自我确认、市场覆盖不足、卖单减少假买入、实时/回放一致、发送前拦截、连续支撑消失、分组与重叠标签偏差，以及成本敏感性。
